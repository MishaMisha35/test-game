# Проверка версии 0.1.0

Проверено в Linux, 24 октября 2026 года. Это результат проверки игрового пролога, а не заявление о готовности полной RPG или релиза в Steam.

## Сборка и повторяемая установка

- `npm test`: **31 unit-тест пройден** (геометрия попаданий, блокирование, валидация и восстановление сохранений).
- `npm run build`: **успешно**, включая строгую проверку TypeScript и production-сборку Vite.
- `npx tsc --noEmit`: **успешно** после финальных изменений тестового стенда.
- Повторная установка из lockfile через `npm ci`, проверяемая установка Electron и повторная production-сборка: **успешно**. Отключение проверки TLS, подписей или контрольных сумм не использовалось.

Команды и результаты:

- `npx playwright test --reporter=list`: NPC/сохранение и бой/возрождение прошли; два остальных сценария потребовали исправления синхронизации стенда.
- `npx playwright test --grep 'menu, real movement|all four wards' --reporter=list`: управление прошло за 55,3 с; сценарий босса выявил слишком раннюю отправку F на последних 0,0167 с перезарядки.
- `npx playwright test --grep 'all four wards' --reporter=list`: **1 passed**, полный бой с боссом прошёл; команда завершилась за **1,8 мин**.

Исправления стенда: ожидание кадра между двумя Escape, ожидание полного нуля cooldown, лимит 240 с для медленного программного рендеринга, ожидание двух игровых секунд при проверке стены. Ранние прогоны также прерывались при перезагрузке Vite и настройке захвата изображения. Проверки не отключались, функции урона не подменялись.

Использованы настоящий ввод клавиатуры/мыши, Rapier, геометрия ударов, снаряды, AI и игровые награды. Для подготовки отдельных ситуаций стенд перемещает актёров, задаёт недостающее здоровье для проверки зелья/смерти и меняет живые данные после сохранения для проверки восстановления. В полном прохождении HP врагов, урон и ресурсы не обходились: использованы обычные атаки, зелья и естественное восстановление выносливости. Ни в одном успешном сценарии не было `pageerror`.

CI использовал Chromium `/usr/bin/chromium`, SwiftShader, игровой режим Performance и render pixel ratio **0,5**. Это функциональная проверка на программном GPU, **не аппаратный FPS-бенчмарк**. Производственные настройки игры ради тестов не изменялись. Скриншоты меню, игрового HUD, смерти и победы записаны в системную временную папку (`eternal-realms-*.png`).

## Нативная упаковка

Оба финальных нативных сценария завершились с **кодом 0**:

| Запуск                                                                                                                                                 | Подтверждённый результат                                                                                                                                                                                       | Отчёт                                        |
| ------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| Development Electron, `DISPLAY=:99 ETERNAL_TEST_NO_SANDBOX=1 node scripts/smoke-desktop.mjs`                                                           | Меню и настоящая 3D-сцена: 190 объектов, canvas 1440×876; клавиша W переместила героя с z=17 до z=16,37 без проваливания; F11 включил нативный fullscreen; локальное сохранение записано; `rendererErrors: []` | `test-results/desktop/results.json`          |
| Упакованное приложение Linux, `DISPLAY=:99 ETERNAL_TEST_NO_SANDBOX=1 node scripts/smoke-desktop.mjs "release/Eternal Realms-linux-x64/Eternal Realms"` | Прямой запуск готового ELF-приложения без сервера и отдельного браузера; та же 3D-сцена, реальное передвижение по земле, нативный fullscreen и локальное сохранение; `rendererErrors: []`                      | `test-results/desktop-packaged/results.json` |

В обеих папках записаны `desktop-menu.png` и `desktop-playing.png`. Сначала снято меню с полными производственными настройками, затем через настоящее действие настроек включён Performance для программного рендеринга SwiftShader. Эти проверки не подтверждают аппаратную частоту кадров или минимальные системные требования на компьютерах игроков.

Виртуальный дисплей использует уже установленные Xorg и xfwm4 без композитинга. Команда `bash scripts/start-test-display.sh` восстанавливает его после потери процессов; установки системных пакетов не требовалось. `ETERNAL_TEST_NO_SANDBOX=1` используется только для ограниченного контейнера проверки: в поставляемом launcher этот флаг не задан, а изоляция renderer остаётся включённой.

Ранние нативные проверки выявили ограничения стенда: ожидание передвижения по короткому реальному таймеру на медленном software GPU и отсутствие оконного менеджера для fullscreen. Кроме того, Playwright `page.keyboard` обходит Electron `before-input-event`. Финальный стенд ждёт реальное изменение позиции и отправляет F11 через `webContents.sendInputEvent`, проверяя существующий обработчик приложения; логика fullscreen и игровая физика не подменялись.

### Готовые архивы

- `release/Eternal-Realms-0.1.0-Windows-x64.zip`: создан, примерно 152 MiB; внутри настоящий PE32+ executable Windows x64.
- `release/Eternal-Realms-0.1.0-Linux-x64.tar.gz`: создан, примерно 120 MiB; внутри настоящий ELF x64 с правами исполнения 755.
- `cd release && sha256sum -c SHA256SUMS.txt`: контрольные суммы игровых архивов прошли проверку.
- `unzip -tq Eternal-Realms-0.1.0-Windows-x64.zip`: ошибок сжатых данных нет. `tar -tzf Eternal-Realms-0.1.0-Linux-x64.tar.gz`: успешная распаковка списка, код 0.
- Проверены структура каждого архива, executable, `resources/app.asar`, `START-HERE.txt`, лицензии Electron и Chromium. В ASAR включены только renderer, desktop entry и минимальный manifest; упакованный renderer соответствует финальному `dist/`.
- Архивы созданы из официальных дистрибутивов Electron 45.0.0 с проверкой SHA256; проверки целостности или TLS не отключались.

Windows x64: выполнены кросс-упаковка, проверка формата PE и целостности архива; **запуск на настоящей Windows не выполнялся**. Windows-приложение не подписано сертификатом. Проверка Steam-клиента, Steam Deck и публикация в Steam не проводились.
